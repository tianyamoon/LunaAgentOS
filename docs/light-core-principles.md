# LunaAgentOS 轻核心原则

## 目的

第一版不能做重。

原因很简单：

- Agent 本身已经很吃资源
- 普通懂点开发的人也要能直接用起来
- 我们需要的是真实入口，而不是大而全平台

## 最轻、最核心的一点

如果只保留一个核心价值，LunaAgentOS 第一版最该保留的是：

**统一入口 + 状态可见。**

也就是：

- 用户保留现有 Agent
- LunaAgentOS 不抢底层运行时
- 但它把任务状态、工具过程、最终结果统一收进一个轻桌面工作台

## 第一版要轻到什么程度

### 对用户来说

第一版最好做到：

- 打开快
- 不要求复杂部署
- 就算只懂一点开发，也能理解怎么用
- 看一眼就知道哪个 Agent 在做什么

### 对实现来说

第一版不应该依赖：

- 重数据库
- 重后端平台
- 复杂云端控制面
- 过度自动化体系

## 从竞品学到的轻核心

### amux

学它：

- watchdog 思维

不学它第一版就做得太重的部分：

- 完整 control plane 运营台

### Goose

学它：

- 统一入口
- 不强迫用户换已有订阅

不学它第一版就做得太满的部分：

- 完整 Agent 产品大生态

### Fusion

学它：

- 任务状态清晰
- 流程可见

不学它第一版就做得太重的部分：

- 多节点工厂化编排
- 大型任务层级体系

## 当前轻核心落地口径

LunaAgentOS 第一版只需要先证明这件事：

**普通懂点开发的人，可以在一个轻量桌面控制台里，统一看见多个 Agent 的工作状态，并完成任务闭环。**

## 做与不做

### 做

- 统一入口
- 状态可见
- 任务闭环
- 轻桌面体验

### 不做

- 重平台
- 重企业治理
- 大而全生态
- 一次性兼容所有 Agent
