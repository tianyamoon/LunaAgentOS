# LunaAgentOS 架构总览

## 核心定位

LunaAgentOS 是一个面向多 Agent 的统一控制层。

它不替换现有 Agent，而是在它们之上建立：

- 统一接入
- 统一状态机
- 统一消息流
- 统一人类工作台
- 统一归档与观测

## 总体分层

```text
┌──────────────────────────────────────────────┐
│                Desktop Shell                 │
│     窗口 / 布局 / 系统集成 / 生命周期         │
├──────────────────────────────────────────────┤
│                  UI Layer                    │
│ Agent 列表 / 输出区 / 状态流 / 工具面板 / 审批 │
├──────────────────────────────────────────────┤
│                   Core                       │
│ 状态机 / 事件总线 / 进程管理 / 协议执行        │
├──────────────────────────────────────────────┤
│                Adapter Layer                 │
│ stdio_json / stdio_text / MCP / Bridge       │
├──────────────────────────────────────────────┤
│              External Runtimes               │
│ Claude Code / Hermes / Trae IDE / ...        │
└──────────────────────────────────────────────┘
```

## 各层职责

### 1. Desktop Shell

职责：

- 提供桌面应用入口
- 管理窗口与生命周期
- 承载控制台布局
- 负责与系统集成

当前倾向：

- 主推荐：`Tauri 2`
- 备选：`Avalonia`

### 2. UI Layer

职责：

- 展示 Agent 列表
- 展示当前输出
- 展示状态流
- 展示工具调用
- 提供人类输入与审批入口

第一版最小界面建议：

- 左侧 Agent 区
- 中间输出区
- 右侧或底部状态 / 工具区
- 顶部或底部任务输入区

### 3. Core

职责：

- 维护生命周期状态机
- 维护统一消息格式
- 驱动事件总线
- 管理任务流转
- 管理进程与会话

这层是 LunaAgentOS 的真正核心。

### 4. Adapter Layer

职责：

- 读取插件 `manifest`
- 启动外部运行时
- 清洗日志
- 解析输出
- 推断状态
- 归一化为统一事件

第一阶段重点：

- `stdio_json`
- `stdio_text`

后续阶段：

- `MCP`
- `HTTP / Gateway`
- `IDE Bridge`

### 5. External Runtimes

这是被 LunaAgentOS 接管的现成 Agent 或产品：

- `Claude Code`
- `Hermes`
- `Trae IDE`

它们不被重写，只被接入。

## 当前三家样板在架构中的位置

### Claude Code

- 角色：强大样板
- 类型：CLI-first / 高价值目标
- 作用：证明 LunaAgentOS 能接住高端 Agent

### Hermes

- 角色：通用样板
- 类型：CLI/Gateway 友好目标
- 作用：最适合作为首个现实 Adapter

### Trae IDE

- 角色：免费样板
- 类型：IDE-first 桥接目标
- 作用：扩大影响力与用户入口

## 当前关键原则

### 原则 1：协议优先于实现语言

核心协议必须保持语言无关：

- `manifest.json`
- 生命周期状态机
- 统一消息格式

### 原则 2：控制层轻，运行时重

Agent 自身已经消耗很多资源，LunaAgentOS 应尽量轻量，避免控制层反过来成为主要负担。

### 原则 3：样板优先于大全

先把最有代表性的三类样板打清楚，不急于兼容所有 Agent。

## 第一版的最小架构闭环

```text
用户输入
  -> Desktop Shell / UI
  -> Core
  -> Adapter
  -> Agent Runtime
  -> 标准化事件流
  -> UI 状态更新
```

第一版不追求全功能，只追求这条链稳定成立。
