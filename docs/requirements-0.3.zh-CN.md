# LunaAgentOS 0.3 需求定义

[English](./requirements-0.3.md)

LunaAgentOS 的长期方向是 AI 时代的个人 Agent 操作系统。

0.3 是这条路上的下一个路标：在 0.2 的工作台底盘上，让用户能真正管理自己的 Agent 入口，并让每张 session card 更像一个正在推进的任务，而不是一段松散的输出记录。

## 0.3 做什么

0.3 聚焦两块：

- **Agent 可用性管理**：用户打开 LunaAgentOS 后，应该知道每个 Agent 能不能用、为什么不能用、适合做什么、怎么把它调到可用状态。
- **Session 卡片任务化**：用户看一张 session card 时，应该知道这个任务现在是什么状态、发生了什么、产出了什么、下一步能怎么继续。

这两块足够大，也足够贴近现在的产品基础。

## Agent 可用性管理

Agent Fleet 不应该只是一个入口列表。它应该逐步变成用户管理 Agent 工作环境的地方。

每个 Agent 至少需要被管理这些信息：

- **身份信息**：Agent 名称、provider、profile、账号身份、运行位置、默认工作目录。
- **模型管理**：可用模型、默认模型、推荐模型，以及不同模型适合的任务。
- **能力边界**：是否能读写文件、运行命令、联网、处理图片、操作浏览器、接入本地仓库。
- **健康状态**：是否安装、是否登录、CLI 是否可调用、环境变量是否完整、WSL 或 bridge 是否可用、版本是否过旧。
- **修复建议**：不可用时，不只显示失败，还要告诉用户下一步应该检查什么。
- **最佳实践**：这个 Agent 适合什么、不适合什么、怎样给任务更稳、交接时应该带什么上下文。
- **安全边界**：这个 Agent 当前允许做什么，哪些动作需要用户确认。
- **资源意识**：先不做完整计费系统，但要为模型额度、上下文浪费、昂贵 runtime 提醒留下位置。

0.3 的目标不是自动修好所有环境问题，而是让用户不再靠猜。

## Session 卡片任务化

Runtime Session Card 是 LunaAgentOS 的中心对象。0.3 需要让它从“过程展示”变成“任务管理界面”。

每张卡片至少应该更清楚地表达：

- **任务身份**：这张卡在做什么，属于哪个 Agent，来自哪个入口或 profile。
- **任务状态**：等待输入、运行中、等待确认、卡住、失败、完成、已归档、历史只读。
- **过程层级**：默认看到关键进展和结果，需要时再展开 thought、tool、runtime event、debug 信息。
- **产物摘要**：最终回答、文件变更、运行过的命令、错误、下一步建议、可交接摘要。
- **动作入口**：继续、重试、归档、标记完成、标记失败、生成交接摘要、发送给另一个 Agent。
- **上下文选择**：交接时可以选择原始任务、最后回答、错误日志、文件 diff 摘要或手动补充说明。
- **关系信息**：这张卡从哪里来，是否是某张卡的继续、重试、分支或交接结果。

卡片不应该逼用户读完整日志才能知道任务发生了什么。

## 两块怎么连起来

Agent 管理回答“谁能干活”。Session 卡片回答“活干到哪了”。

0.3 里这两块应该连起来：

- session 卡片上能看到当前 Agent 的关键健康状态。
- Agent 不可用时，卡片能解释原因，而不是只失败。
- session 失败或卡住时，可以提示哪些 Agent 可能更适合继续。
- session 完成后，可以生成一份给另一个 Agent 的交接摘要。
- handoff 始终以用户明确触发为前提，保留人类控制；自动多 Agent 协作是后续阶段的命题。

## 0.3 的最小可发版范围

如果要控制范围，0.3 可以先做到：

- Agent 详情面板。
- Agent 健康检测和配置诊断。
- Agent 模型、能力、profile、运行位置的基础展示。
- 每个 Agent 的最佳实践说明。
- Session card 状态系统。
- Session card 的简洁视图、过程视图和调试视图。
- Session 结果摘要区。
- 继续、重试、归档、标记完成、标记失败。
- 第一版手动 handoff：选择上下文，生成摘要，发送给另一个 Agent 或 session。

## 不在 0.3 范围内的东西

以下路标在后续版本逐步展开：

- 完整自动多 Agent 编排。
- Agent 之间自动互相调用。
- Agent marketplace。
- 团队模式。
- 完整计费与预算平台。
- 跨 Agent shared memory bus。

这些是 LunaAgentOS 走向完整操作系统路上的后续路段，不在 0.3 的发布承诺里。同时明确：adapter 是翻译层，不是同化层——每个外部 Agent 保留自己的内部机制。

## 和现有路线图的关系

这页是把下一步说具体，不改动 LunaAgentOS 的定义。

方向仍然是 AI 时代的个人 Agent 操作系统。0.3 在 0.2 的工作台之上，先把操作系统里最基础的两件事做扎实：

- 管理可用的执行入口。
- 管理正在发生的任务。

这两块稳下来之后，后续版本顺势推进更强的 handoff、collaboration、control plane 和更完整的 operating layer。
