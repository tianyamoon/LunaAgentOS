# LunaAgentOS 当前开放问题

## 目的

这份文档不是列问题给自己看，而是明确告诉未来参与者：

- 哪些问题已经定了
- 哪些问题还没定
- 哪些地方欢迎参与和争论

## 已基本定下的方向

### 1. 产品定位

LunaAgentOS 是“统一控制层”，不是单一 Agent。

### 2. 第一批样板

- `Claude Code`：强大
- `Hermes`：通用
- `Trae IDE`：免费

### 3. 当前协议重心

- `manifest`
- 生命周期状态机
- 统一消息格式

### 4. 当前技术倾向

- 主推荐：`Tauri 2 + Rust Core`
- 备选：`Avalonia + C#`

## 仍然开放的问题

### 1. 第一版桌面壳到底先选哪条线

虽然当前技术倾向已收口，但还没到真正落桌面代码的阶段：

- 直接上 `Tauri 2`
- 还是先做 `Avalonia` 原型

这是后续的重要决定点。

### 2. Hermes 的最优接入面是什么

需要进一步确定：

- 纯 CLI 模式
- Quiet / pipe 友好模式
- 还是 Gateway 模式

### 3. Claude Code 的现实接入深度

需要区分：

- 能否稳定作为 CLI runtime 接管
- 是否要直接走更结构化的事件面

### 4. Trae IDE 的桥接方式

这是当前最大的开放问题之一。

候选方向：

- 桌面自动化
- IDE 插件桥
- 内部终端桥接
- 会话代理进程

### 5. 第一版桌面控制台交互是否先做极简

要不要第一版就包含：

- 多面板
- 右侧归档
- 工具调用面板
- 人类审批流

还是先只做最小闭环。

### 6. Plugin SDK 的边界

需要后续定义清楚：

- 哪些是稳定接口
- 哪些是实验性能力
- 外部贡献者能补到什么程度

## 当前建议

现在最值得参与者帮忙推进的，不是泛泛讨论，而是以下几个具体问题：

1. `Hermes` 接入面验证
2. `Claude Code` 接入面验证
3. `Trae IDE` Bridge 方案研究
4. 桌面壳技术原型比较
5. 最小控制台界面定义
