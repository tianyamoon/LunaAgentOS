# 版本路线

## 总体判断

LunaAgentOS 的推进不应该按“功能越多越好”来走，而应该按“先拿到真实产品价值，再逐层外扩”来走。

当前最稳的路线是：

- `v1`：替代 Claude CLI 入口
- `v1.1`：证明异构接入成立
- `v2`：跑通调用流
- `v3`：长成控制平面

## v1：替代 CLI 入口

### 目标

让用户不必直接进入 `Claude Code CLI`，而是通过 LunaAgentOS 桌面工作台来使用它。

### 核心能力

- 左侧 provider / agent 舰队
- 主 agent 设定
- 中间主 agent 多会话卡片
- 卡片展示输出流 / 思考流 / 最终响应
- 右侧历史任务
- 历史按日期 JSON 存储
- `Claude Code` 真实可用
- 启动轻、静默、不打断用户

### 产品价值

这一版不是替代 Claude 的模型能力，而是先替代它的 CLI 使用入口。

## v1.1：从单入口变成双入口

### 目标

把 `Hermes` 的真实执行链路接通，让 LunaAgentOS 从单一 Runtime 入口变成异构入口。

### 核心能力

- `Hermes in WSL` 真实执行
- 主 agent 可选 `Claude / Hermes`
- 多会话体验继续稳定
- 历史任务支持回看
- 会话状态持久化更完整
- 启动与异常处理更稳

### 产品价值

这一版的意义是证明：

LunaAgentOS 不是 Claude 专用壳，而是真正能承接多种 Agent Runtime 的桌面控制台。

## v2：从主 agent 走向调用流

### 目标

让主 agent 可以唤起其它 agent，开始形成真正的协作工作台。

### 核心能力

- 主 agent 接收用户输入
- 主 agent 在需要时唤起副 agent
- 新 agent 卡片入场
- 多卡片并存协作
- 基础调用流可见
- 人类能够看到“谁在调谁”

### 产品价值

这一版意味着 LunaAgentOS 不再只是单入口工具，而开始具备真正的 Agent 工作台特征。

## v3：控制平面雏形

### 目标

从工作台升级到控制层。

### 核心能力

- provider 管理器
- agent 生命周期管理
- 会话恢复
- 人类审批流
- 任务分发
- 归档与回放
- 多 runtime 编排
- 更完整的状态观测

### 产品价值

这一版对应的是最初的方向：

LunaAgentOS 开始长成异构 Agent 之上的控制平面，而不是单纯桌面入口。

## 当前执行建议

如果只看最近一段时间的节奏，建议严格按这个顺序推进：

1. 先做完 `v1`
2. 再接通 `Hermes`
3. 再碰调用流
4. 最后才碰更完整的控制平面

一句话总结：

**先拿到入口价值，再拿到异构价值，再拿到编排价值，最后才拿到控制平面价值。**
