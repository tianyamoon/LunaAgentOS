# LunaAgentOS Target Matrix

## Product framing

The current LunaAgentOS sample set follows the user's value-oriented wedge rather than a pure protocol-oriented shortlist:

- `Strongest`: Claude Code
- `General`: Hermes
- `Free`: Trae IDE

This is intentionally a product mix, not three equivalent transport surfaces.

## Engineering classification

| Target | Product role | Current surface | Phase fit | Notes |
| --- | --- | --- | --- | --- |
| Claude Code | Strongest sample | CLI / MCP-friendly | Phase 0 | Native CLI adapter target |
| Hermes | General sample | CLI / Gateway | Phase 0 | Best first real adapter target |
| Trae IDE | Free sample | IDE-first | Phase 0.5 / 1 | Needs bridge strategy, not a fake stdio manifest |

## Why this matters

If LunaAgentOS only chooses "the easiest three CLIs," the product story gets weak. This trio is stronger because each target proves a different kind of value:

- Claude Code proves premium relevance.
- Hermes proves adapter practicality.
- Trae IDE proves growth potential through a free user wedge.
